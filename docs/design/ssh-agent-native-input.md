# SSH Agent 原生输入与命令候选设计

日期：2026-10-13。状态：设计提案，尚未实施或运行验收。

调查基线：当前工作树，HEAD 为 `ed4e9964794f9a09887a1a7e25eb5e02f165b31e`。工作树有其他进行中的修改，HEAD 不代表所有调查文件的完整快照。本次仅新增本文档。

## 1. 目标与主要决定

SSH 高延迟时，用户在远端 agent TUI 内输入文字，需要等待远端处理按键并回传画面。目标是让编辑、中文输入和已同步命令的筛选在本机即时完成，用户点击发送后再提交完整内容，同时保留 `/` 命令候选。

采用“App 原生交互界面 + 远端 agent 协议适配”方案：

1. 对经过验证的 agent，复用仓库已有 ACP（Agent Client Protocol）适配、会话事件和命令菜单。远端执行 agent，本地负责输入和展示。
2. 增加“Agent 原生输入（实验性）”开关，默认关闭。开启只改变新建 agent 会话的默认交互方式，不接管已有 TUI。
3. 命令候选来自当前远端会话报告的能力，提前同步并在本地筛选。不能用一份写死的命令列表冒充当前 agent 的完整功能。
4. 不支持协议、版本不兼容或未通过验收的 agent 继续使用原 TUI。不会将纯文本批量注入包装为等价的协议交互。
5. 该功能不是正在运行的 TUI 的透明输入代理；不承诺复刻其全部菜单、快捷键、插件界面和动态参数补全。

本设计补充 [SSH 后端设计](ssh-direct-backend.md)；窗口重开时的资源接回遵守 [窗口恢复设计](ssh-workspace-window-restore.md)，不得因恢复视图而创建新 agent 或重发输入。

| Amp、Oh My Pi、Copilot、Mistral Vibe、Kimi Code、Grok、Cursor Agent、Droid 等其余预置 | 尚无本文核实的对应 ACP 接入 | 首版保留原 TUI。尤其 Oh My Pi 与 Pi 是两个 agent，不共用支持结论。 |

“可用”至少要求：发行包包含所需适配资源、目标 CLI 版本满足验证范围、当前身份能完成协议握手，并能处理正常回复、错误、取消和所需的用户确认。命令列表是会话级能力，应在握手后另行显示状态，不能只根据品牌判断。

## 4. 功能开关与会话生命周期

### 4.1 设置定义

在 SSH 工作台的设置中增加一个应用级布尔开关：

- 名称：**Agent 原生输入（实验性）**。
- 说明：**为支持的 Agent 使用本地编辑和命令候选。仅影响新会话，其他 Agent 使用终端。**
- 默认值：关闭；配置缺失、损坏或来自旧版本时按关闭处理。
- 建议内部键：`agentNativeInputEnabled`，这是拟新增字段，不是现有设置键。
- 范围：当前 Superset Remix 桌面配置目录，全局影响该配置内的新建 SSH agent 会话；不同机器仍独立探测能力。
- 存储：桌面主进程在现有 `userData/direct-workstation` 下的本地 SQLite 偏好表持有，renderer 通过受校验 IPC 读取和更新；不修改远端配置，不同步到上游 Superset 目录。实施时按仓库迁移规范增加表或字段。
- 更新后立即反映在新建会话界面，重启后保留。开关本身不连接机器、不安装 CLI、不触发新权限请求。

首版不增加机器级和 agent 级持久开关，避免优先级冲突。新建会话面板始终提供“使用原终端”，作为本次创建的显式选择，不覆盖全局设置。

### 4.2 生效规则

| 操作或状态 | 行为 |
| --- | --- |
| 开关关闭，新建会话 | 沿用原 TUI 启动路径。 |
| 开关开启，agent 在首版支持列表且后端具备能力 | 新建原生交互会话；显示连接/准备状态，握手完成后才能发送。 |
| 开关开启，agent 不支持或旧后端缺少能力 | 创建前明确显示“将使用原终端”，沿用原 TUI；不静默下载适配器或升级后端。 |
| 打开或关闭开关时已有 TUI | 继续原进程和原界面，不自动切换。 |
| 关闭开关时已有原生会话 | 保持该会话可用，提示“已打开的会话保持当前模式”；新建会话使用原 TUI。不能把设置开关实现为杀进程。 |
| 应用重开、窗口恢复 | 按保存的会话类型恢复同一个资源，不根据当前开关把已有会话转换为其他类型。 |
| ACP 已开始创建但握手失败、超时或状态未知 | 展示错误并保留会话引用；查询创建操作结果，不能自动再启动一个 TUI。 |

首版不提供运行中 TUI 与 ACP 的原地转换。界面可提供“新建终端会话”，但须表明这是新会话；不会把现有原生任务偷偷迁移或同时绑定两个执行进程。未来若增加“从历史继续”，须单独验证供应商会话 ID、单一写入者和明确的停止/恢复流程。

## 5. 输入和候选交互

### 5.1 本地编辑

采用原生聊天面板：上方显示消息、工具执行及确认请求，下方显示多行编辑区和发送按钮。它呈现结构化事件，不尝试在 xterm 画面上覆盖输入行。

- 打字、删改、撤销、光标移动、中文输入法组词全部在本地处理，不逐键发送。
- Enter 在候选打开时只选择候选；候选关闭时发送，Shift+Enter 换行。输入法 composition 期间 Enter 只确认组词，不能误提交。
- 选择命令只插入命令和可选参数占位，不自动执行。按 Tab 选择候选、Esc 关闭菜单，上下键切换候选。
- 发送时锁定该次输入快照和操作 ID；用户随后编辑的新草稿不能被旧请求完成回调清空。
- 正在执行、等待审批和离线分别显示状态。首版不新增消息队列或自动 steering；只有会话明确允许普通提交时才启用发送，其他时候仍可编辑草稿。

### 5.2 `/` 命令候选

会话收到协议命令更新后保存完整列表。输入首个 `/` 时本地展示，继续输入时按名称/说明筛选。候选内容只渲染为文本，不执行命令说明、HTML 或链接中的指令。

区分四种状态：

| 状态 | 展示与处理 |
| --- | --- |
| 还未收到列表或不支持提供列表 | 显示“命令列表暂不可用”；不套用其他会话的列表，不因没有候选禁用普通文本输入。 |
| 明确收到空列表 | 显示“此会话未提供命令”；不显示加载动画。 |
| 已收到非空列表 | 展示名称、说明和可选参数提示，使用本地筛选。 |
| 断线或重连尚未核对 | 旧列表标为待更新，可供浏览和编辑，禁用发送；握手及会话核对后更新。 |

更新列表采用替换语义，删除的命令立即从候选移除。选中项按命令标识保持，消失时清除选择。供应商版本、工作目录、插件和当前模式都可能影响列表，不能仅用 agent 名称做全局缓存键。

发送 `/command` 前使用最新已知列表进行检查：列表尚未就绪时要求等待或明确选择“仍发送原文”；完整列表已就绪但未包含该命令时显示“此模式未提供该命令”，保留草稿，不静默转成普通提示词。协议报错时展示真实原因，不自动换成 TUI 重试。识别 slash 命令需沿用供应商适配的语法，不能将所有以 `/` 开头的文件路径都认作命令。

“仍发送原文”只是不经过本地候选校验，供应商仍可能将它解析为命令；界面说明“由 Agent 解释此内容，可能不受支持”。不把它标为“按普通文本发送”，因为协议没有统一的 slash 转义保证，也不把它当成执行未知 TUI 指令的替代方案。

### 5.3 文件和动态参数候选

`availableCommands` 现有字段只描述命令及参数提示，不能用于推断所有动态候选。

- `@` 文件候选复用当前远端工作区的文件搜索，采用短防抖和输入版本号，丢弃迟到响应；网络请求不阻塞打字。
- 已有结果可本地筛选；新查询仍需要网络往返，显示加载状态，不承诺即时出现全部远端文件。
- 实施时核对 SSH RPC 允许列表，并以已认证工作区约束路径；不引入 dashboard 的云页面搜索和 hosted MCP 依赖。
- 模型和模式优先使用会话协议已有的结构化选项。没有接口的交互不伪造候选，提示使用原终端新建会话。
- 自定义命令与插件命令只在 agent 实际上报并经过兼容性验证时显示；不会从终端输出正则猜测完整菜单。

## 6. 数据流与接入边界

```text
本地原生编辑器 ──点击发送──> 桌面主进程操作记录
       ↑                            │
本地命令菜单                         │ 现有认证通道 / SSH 转发
       ↑                            ↓
会话 availableCommands <── 远端 chat runtime <──> ACP adapter <──> agent
       ↑                     │
       └──会话事件流───────────┘
```

继续复用现有连接 generation、backendId、namespaceId、工作区授权和操作记录。协议能力不会开一个额外公网监听端口，也不要求用户部署独立代理。

需要完成的接入：

1. 在直连 describe 中增加可选、版本化能力，例如拟议的 `agentNativeInputV1`；保留旧字段和旧 harness ID 的含义。
2. 由实际 harness 注册结果和 CLI 检查产生候选可用性，并区分“可尝试连接”和“会话握手成功”。客户端只接受实现并验收过的 harness；旧后端缺字段按不支持处理。
3. 扩展主进程能力过滤、共享类型和新建会话选择，明确 `presetId → harnessId` 映射；不根据同名品牌合并旧 chat 和 ACP。
4. 在 SSH 原生会话组件中复用命令菜单和输入组件，通过现有 chat 事件 reducer 读取 `availableCommands`；可选字段缺失时兼容处理。任何新 RPC 必须遵守 tRPC 向后兼容规范。
5. 将最低版本、适配器版本、执行环境和所需资源纳入后端发行包检查，在最终包内验证；不因包内缺资源在首次输入时偷偷安装依赖。
6. 沿用当前 agent 的身份和授权策略；本功能不应额外启用跳过审批。原生界面必须呈现协议中的权限请求和问题，无法处理的必需交互应视为该适配不可发布。

能力标志和偏好键均为设计名称。全局能力只说明后端理解协议，不能替代逐 agent 及逐会话的就绪状态。首版启用还要求后端具备 `durableOperations` 和相应结果查询能力；缺少它们的新会话使用原 TUI，已有原生会话只能查看已取得的信息并提示连接兼容后端，不能悄悄退回没有持久操作记录的发送路径。

## 7. 状态、断线与提交正确性

本地草稿和命令列表按 `connectionId + backendId + namespaceId + workspaceId + sessionId + harnessId` 隔离。事件和请求另带当前连接 generation、会话 epoch/事件 cursor；迟到响应不能更新切换后的会话。

首版草稿只在应用内存中保留：切换标签、短时断线、关闭设置面板均不丢失，应用退出后不保证恢复。关闭有未发送草稿的会话视图时提供保留/放弃选择。若现有窗口退出流程不会提示未发送内容，实施时增加统一草稿提示，不承诺已落盘。命令缓存随会话回收，设置布尔值持久化，三者不能混用。

建议首版限额：单草稿 256 KiB、最多 20 个保留草稿；单会话候选最多 2,000 项且文本总量不超过 1 MiB。它们是拟定资源上限，实施时与既有消息上限取较小值。到达草稿上限时提示用户处理，不静默丢弃；候选超限标明列表不完整，对列表外的命令采用上文“列表尚未就绪”的显式发送选择，不能当作完整列表直接拒绝。普通文本和已列出的命令仍可正常提交。

提交路径继续使用持久操作记录：

- 点击发送生成一次操作 ID，并固定目标会话和内容；重复点击合并为同一操作。
- 请求前已断线：保留草稿，不入自动发送队列。
- 发出后失去响应：显示“正在确认发送结果”，使用原操作 ID 查询；不能把超时等同于失败并用新 ID 重发。
- 确认已接收：将该次草稿记为已发送；只清除仍与该次快照一致的草稿。
- 确认未接收：允许用户显式重试。结果不确定时保持不确定，不自动重发或自动切到 TUI。
- 重连先核对远端身份及原会话，再恢复事件订阅和更新候选；不通过创建同名新会话冒充恢复。

开关改变、关闭窗口或断线不取消远端执行；“停止任务”是独立操作。供应商执行与后端持久记录之间仍可能有崩溃窗口，不能宣称严格一次执行。

## 8. 实施顺序

1. 核实 Claude、Codex 的指定 CLI/适配器版本、命令上报、权限交互、会话恢复能力，记录支持和缺失的 TUI 功能。
2. 增加默认关闭的偏好和新会话模式选择，覆盖开关持久化、旧后端和已有会话的行为。
3. 贯通 ACP 后端打包、直连能力、主进程过滤、共享类型与原生面板；先实现文字输入和 `/` 菜单。
4. 接入工作区文件搜索、模式选择及错误呈现，完成会话隔离、发送确认和断线恢复。
5. 使用真实 SSH 和最终安装包完成首批 agent 验收后，才允许打开开关使用对应适配。
6. Gemini、OpenCode、Pi 分别通过同样的验收再加入支持列表，其余继续使用原 TUI。

## 9. 验收标准

以下为计划检查，不是已通过结果。逻辑测试使用可控事件与时钟；网络延迟和原生窗口观察放在单独的端到端验收中。

| 场景 | 必须满足的结果 |
| --- | --- |
| 默认关闭与升级 | 旧配置缺少键时仍走原 TUI；开关重启后持久保留。 |
| 开关切换 | 已有 TUI/原生会话的执行实例不变；无停止、新建或额外 prompt；新会话遵守新设置。 |
| 旧后端、缺适配包、版本不支持 | 创建前显示原因并提供原 TUI；ACP 创建结果未知时不自动创建第二个进程。 |

| 窗口恢复 | 恢复原会话类型、身份和输出；不会由当前开关触发会话转换或自动提交草稿。 |
| 可访问性与语言 | 键盘操作、焦点、候选读屏及小窗口布局可用；文案经 Lingui 翻译，不显示实现术语作为主要操作。 |
